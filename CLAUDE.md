# etf-momentum-ios — Claude instructions

SwiftUI reader for the ETF Momentum leaderboard. Scoring, the database and the
web dashboard live in jbarte/sector_momentum. Design docs are in the private
companion repo jbarte/sector_momentum-notes:
specs/2026-09-17-ios-board-app-design.md and plans/2026-09-19-ios-board-app.md.

## Git workflow

Branch before changing anything (`feature/<slug>` or `fix/<slug>`), commit with
conventional commits, run `/code-review`, push, open a PR with `gh pr create`,
and stop: Jonas reviews and merges. Delete a branch only after
`gh pr list --head <branch> --state all --json state` says MERGED.

## Architecture

The setup of jbarte/dependency-demo: Point-Free's swift-dependencies, one root
`Package.swift` holding every module as a target, and a thin, hand-maintained
Xcode app in `App/` that links only `AppFeature`.

- `MomentumKit` — the board rules. Pure Swift, no dependencies.
- `…Client` — a `@DependencyClient` interface with an unimplemented
  `testValue`, a `previewValue`, and ready-made `.mock`/`.failing` values.
  `FeedClient` and `BoardCacheClient` carry their small live values inline.
- `SupabaseLive` — the live `SignInClient` and `ScoresClient`, sharing one
  Supabase client. The only module that builds supabase-swift.
- `…Feature` — an `@Observable` model resolving clients with `@Dependency`,
  its views and previews (`#Preview(traits: .dependency(...))`).
- `AppFeature` — the composition root and the only module that links
  `SupabaseLive`.

Rule: features and their tests see client interfaces only. Tests nest in a
`BaseSuite` marked `@Suite(.dependencies)`.

## Rules that must match Python

MomentumKit re-implements sector_momentum's board rules: the Enter/Exit band,
rank delta and trend. **Python is the reference** (dashboard/rows.py,
src/horizons.py).

- Never change a rule here without the Python side changing first.
- `Tests/MomentumKitTests/Fixtures/band-fixture.json` is generated by
  sector_momentum's dashboard/band_fixture.py. Refresh it with
  `scripts/update-fixture.sh` and never edit it by hand. CI fails when it
  drifts from the published copy.
- Never hardcode top_n, buffer_frac, horizon keys or cohort regions; they come
  from data.json's `config` block.

## Gated data

`v_recent_scores` is signed-in-only content. Never commit rows from it. Test
fixtures use synthetic rows or the already-public data.json.

## Commands

    swift test                                  # every module's tests, on the Mac
    open App/ETFMomentum.xcodeproj              # Run, or ⌘U for the same tests on iOS
    scripts/check-fixture.sh                    # vendored fixture == published one

From the command line, `xcodebuild` needs `-skipMacroValidation` (in Xcode,
approve "Trust & Enable" for swift-dependencies' macros once). Run the app with
the launch argument `-UseStubData` for a real config with invented scores and
no sign-in.
